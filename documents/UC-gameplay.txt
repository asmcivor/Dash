Use Case: Game Play
* Actor: Student
* Goal: The basics of the game play
* Preconditions: Actor has accessed the web page
* Trigger: Accesses website/flashcard
* Main flow: Numbered steps, actor action ? system response, alternating

0. Initial page load (see UC-pageload.txt)
1. Student Presses New Game and then presses go button
    1.1 Screen Refreshes.  
        1.1.1 If timer options in enabled then 
            1.1.1.1 The count down value is displayed in the upper right corner on the same line as the option gear. The class name is counter.
            1.1.1.2 When Student clicks start then the timer starts with a descending count for the individual problem.  
        1.1.2  The system Displays 2 numbers with the default operation of last operation 
        used (UC-newproblem.txt). If the timer option is not enabled the system starts with the display of the problem
        1.1.2.1 If the timer option is not enabled then the system Displays 2 numbers with the default operation of last operation used.
2 Student Enters or Updates Answer press return or check button
    2.1 System Reviews the answer (UC-reviewanswer.txt) and if correct turns the border to green (--correct-answer) if wrong then lighter red (--wrong-answer).     If correct add to the stats for the number correct for this session, 
    if wrong add to the stats section for number wrong for this session. Display the running count of total problems, number of correct and wrong answers. 
    2.2 If the timer expires before the answer is entered then the border turns red and the user cannot enter the answer.  The answer is marked as wrong and focus is set to the Next

3 Presses Next
    3.1 Screen Refreshes.  Displays 2 numbers with the default operation of last operation used. If timer option then timer resets to the value set in the options and starts to count down again.
    4.1 System displays the stats for the game just completed.


* Postconditions: Actor leaves the page.
* Alternate/edge flows: What happens on wrong answers, invalid input, edge cases (division by zero, negative results, etc.)
1 User Clicks new operand
    Screen Refreshes.  Displays 2 numbers with the new operand.  Current game counts don't change. Operands include +,-,*,/,Random
2 Enters or Updates Answer press return or check button
    Reviews the answer and if correct turns the border to green (--correct-answer) if wrong then light red (--wrong-answer).  
    If correct add to number correct for this session, if wrong add to the number wrong for this session. Display the running count total problems
    number of correct and wrong answers.
3. User hits page refresh during the game.  The current problem is re-displayed.  QUESTION: on refresh does the timer refresh to default or keep the current value?
